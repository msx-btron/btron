Comparative systems note · C libraries · RTOS hosts

A minimal rt, measured against the field.

B-System include/rt is not a second glibc. It is a reorganised, freestanding-leaning shim: small trusted surface, explicit absences, and the services a workstation actually needs living one layer above the C library.

This note compares that shim with musl, glibc, NuttX libc, newlib / picolibc and dietlibc. Claims stay inside published measurements or inside what each design states about itself. Where B-System has no published binary size, the cell says so.

00 / Method

What is being compared

Objects · criteria · what this note refuses to claim

The objects are C libraries used as the lowest portable layer under an operating system or a bare-metal image. They are not ranked by how many POSIX calls they export. A library that omits locale because the document system owns text is not “incomplete” in the same sense as a library that claims POSIX and then aborts on exhaustion.

Criteria, in order: (1) stated design position, (2) which ISO C headers are actually present, (3) published size class and licence, (4) behaviour when a resource runs out, (5) which host — Linux, RTOS, or freestanding multi-arch — the library is built to sit under.

02 / Surface

Header coverage

Present · partial · absent at the libc layer

The matrix records the library layer only. B-System marks several headers absent because assert must not abort, ctype must not grow locale tables, and time is a plane period rather than clock(). Those choices are specified, not unfinished.

musl, glibc and a full NuttX or newlib configuration implement the same headers because their contract is “a C programmer can include them”. dietlibc implements a subset and documents the rest as missing.

03 / Metrics

Size, licence, exhaustion

Published figures kept separate from design inference

The 6 / 13 / 70 / 662 kilobyte row is a single historical experiment on Linux static linking. It does not measure NuttX, newlib-nano, picolibc or B-System. Using it to declare a winner across RTOS libc builds would be a category error.

04 / Placement

What the host already owns

A libc is only the bottom of a system

musl and glibc assume Linux: processes, mmap, a dynamic linker, a filesystem. newlib assumes the opposite: the port writes _sbrk, _read and _write. NuttX assumes its own kernel pools. B-System assumes BTRON planes, an actor queue, and a document model. Comparing header counts without that sentence flatters the largest library.

Word wrap, complex text, and input method do not belong in B-System rt. They are implemented in the text renderer, TAD segments, windows and language settings. Threads are not pthreads; they are pinned workers and lock-free queues. Time is not a 10 ms tick; the finest plane wakes on a 1 ms period, and the interrupt contract is a 50 µs ceiling, not a measured worst case.

05 / Selection

A decision, not a ranking

Pick the library whose refusal matches the product

musl is already a radical reduction of glibc. B-System rt is a further reduction, and a different kind: it is not trying to be Linux libc at all. Its protection is the size of the surface a reader must trust, the refusal to abort from assert, and the rule that locale, threads and buffered I/O do not enter the bottom layer by default.
