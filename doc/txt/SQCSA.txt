Security and Quality Code Static Analysis
src/  —  2026-11-11

Scope is src/ and the headers it includes. third_party/ is not scanned and
not edited. A scanner hit names a call or a pattern. It is a defect when a
read of that site shows the bad path can run. The three groups used below
are quality, security, and introspection.

2. What already holds

  tkl_strscpy, tkl_strscat, tkl_strpad in src/kernel/libstr.c.
  n is the full capacity, including the NUL. Truncation, n == 0, and a
  NULL argument return (size_t)-1. A positive n always terminates.
  strscpy does not zero the tail. strpad writes exactly n bytes, the
  string and then zeros, and is the copy for a slot that is stored raw.
  tkl_strncpy is unchanged: no NUL when the source is at least n bytes,
  zero-fill when it is shorter. It is not an alias of strscpy.

  make sec-libstr on this date:
    AddressSanitizer and UndefinedBehaviorSanitizer, 23 checks, 0 failed.
    clang --analyze on src/kernel/libstr.c produced no diagnostics.
    cppcheck on that file, with --error-exitcode=1, produced no findings.
    flawfinder --minlevel=4 reported 3 hits, all freestanding aliases:
      src/kernel/libstr.c:500  strcpy
      src/kernel/libstr.c:522  strcat
      src/kernel/libstr.c:941  snprintf
    Those lines are the weak aliases onto tkl_strcpy, tkl_strcat, and
    tkl_snprintf. They stay. No flawfinder: ignore comment was added.

  Freestanding assert() in include/rt/assert.h increments
  btron_assert_count and stores btron_assert_line. It does not abort,
  print, or allocate. The hosted build still uses the system assert.

  tkl_vsnprintf does not implement %n. The store is locked by
  verify/tests/test_printf_float.c: a sink of 42 stays 42.

  PAK and BSP lengths go through btron_span_inside() in
  include/btron/span.h. The sum is formed in size_t after the negative
  check. The hostile pair is ofs = INT_MAX - 8, len = 64. make test-fs-span
  is 10 checks, 0 failed, under UndefinedBehaviorSanitizer. Call sites
  are in src/media/quake/sys/fs_btron.c.


3. This slice: kernel, filesystem, and cores copies

  C-string copies now call tkl_strscpy with the full capacity.
  The one raw slot calls tkl_strpad.

  src/cores/core_init.c
    sys_get_devconf on the PS2, m68k, and other freestanding lanes.
    The hosted lane was already snprintf(buf, bufsz, ...).
    Syntax-checked hosted, -ffreestanding -DBTRON_PS2_TARGET, and
    -ffreestanding -D__m68k__.

  src/kernel/sys_mgmt.c
    set_cnf of CNF_SYS_NAME. get_cnf copies strlen+1, so the name is a
    C string. A 79-byte name comes back as 63 bytes plus a NUL.

  src/kernel/dev_mgr.c
    opn_dev_mgr name[32].

  src/kernel/fs_record.c
    File paths, the sample directory name, and VOL_INFO.vol_name.
    Paths are compared with strcmp. VOL_INFO.vol_name is a 32-byte
    C string, separate from the 40-byte on-disk volume name.

  src/fs/file.c
    fil_get_rec_link_info.
    FileHeader.name is 40 bytes and is not required to contain a NUL.
    The copy into link_name[64] is bounded by sizeof name, so the read
    stays inside the field. The old strncpy used sizeof(link_name)-1
    and could continue into data_blk. The caller buffer uses name_max
    as the full capacity.

  src/fs/vol.c
    Empty B-right/V name. vol_name is 40 bytes and is memcpy'd to the
    volume block (vol.c writes 40 bytes at offset 28). tkl_strpad
    zero-fills that slot. tkl_strscpy would leave whatever sat past the
    new NUL.

  POSIX and QEMU image lists now compile src/kernel/libstr.c. core_init
  and vol.c call into it. Host filesystem tools link libstr.host.o built
  with -DBTRON_LIBSTR_NO_HEAP, so mkbtronfs does not take the image heap.
  The same flag is used for the .test.o, .tgl.o, and verify objects.

  make test-kcopy, AddressSanitizer and UndefinedBehaviorSanitizer,
  15 checks, 0 failed. A 79-byte configuration name and a 79-byte record
  path come back terminated inside the slot. Opening the unclipped path
  fails. "hi" after a long name does not keep the long tail. rd_dir
  returns "sample.tad". ref_vol returns "BTRON_SYSTEM".
  src/fs/vol.host.o and src/fs/file.host.o compiled with -Wall -Wextra.
  The verify recipe's flags compiled vol.c, fs_record.c, sys_mgmt.c,
  dev_mgr.c, and libstr.c.

  tkl_strncpy itself was not edited. Call sites outside this slice were
  not edited.

  disassemblers and TinyGL. Not scheduled ahead of the copy slices.

  arrayIndexOutOfBounds, 12 errors. The checker uses the loop ceiling,
  which is wider than the array. Sites read for this report do not reach
  that ceiling:

    src/apps/chokanji/cab.c:141, :212, :370

7. Categories

  Quality
    Sized copies at the kernel, filesystem, and cores boundary.
    Span checks that do not add two signed ints.
    Loop ceilings that match the arrays (cab, microscript, orchestra),
    so the next scan can see a real index.
    Shift-by-width in the disassemblers and TinyGL.
    Allocation failure paths cppcheck grouped as nullPointerOutOfMemory.
    Format warnings (-Wformat=2) on the verify build, later, not on the
    freestanding image yet.

  Security
    Unbounded strcpy, strcat, and sprintf in the disassemblers.
    Editor access-then-use, and the editor's strlen+1 copy.
    MSX sscanf without a width, and atoi of untrusted ini integers.
    PAK and BSP spans. The hostile pair is rejected. That slice is in.
    Shell execvp and the fixed popen are named by flawfinder. No
    exploit path was shown past "the program runs a command".
    gterm history and quake console history can leave a slot without a
    NUL. Those are the next copy slices, not this one.

  Introspection and error reporting
    Freestanding assert records the line and returns.
    %n does not store.
    tkl_strscpy returns (size_t)-1 on truncation. The kernel setters
    still return their existing code. A new logger was not added.
    cppcheck's two uninitvar hits (bpk_core.c, term.c) are unread
    values, which is this category, and they are not fixed here.
    Kernel CHECK_* and goto error_exit stay.

  check is removed, and runs the suite that directory already has.

    2. Kernel, filesystem, and cores C-string copies. Done in this report.
