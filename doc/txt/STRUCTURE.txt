1. The Story Behind Each Folder
-------------------------------

### tools/
The `tools/` root directory contains offline and host-side development tools,
compilers, volume builders, asset compressors, and debug extractors. Unlike
kernel or guest code, tools execute on the developer's build host (POSIX/macOS/
Linux/Windows) to generate binary artifacts consumed by target architectures:
  - `mkbtronfs`: Compiles textual volume manifests (`manifest.txt`) into native
    B-System hierarchical file storage images (`btron_sys.vol`, `btron_anders.vol`).
  - `album_encode`: Offline encoder compressing audio albums into native ADPCM
    and B-Audio streaming blocks.
  - `dump_mars_assets` & `sim_msx_voxel`: Extraction tools for classic 1993 Mars
    voxel landscapes and real-time simulator prototypes.
  - `capture_screens` / `capture_foma` / `capture_segui`: Automated frame dumpers
    and regression validators driving headless guest framebuffers.


### src/kernel/
The cleanroom μITRON 3.0 / T-Kernel 2.0 microkernel engine.
This subsystem implements the foundational real-time operating system primitives
mandated by the TRON Architecture specifications designed by Dr. Ken Sakamura:
  - Task dispatching, preemptive priority scheduling, and ready queues.
  - Synchronization and communication: semaphores (`sem`), event flags (`flg`),
    mailboxes (`mbx`), message buffers (`mbf`), and rendezvous (`por`).
  - High-resolution hardware timers, clock managers (`clk_mgr`), and alarms.
  - Memory management: fixed block pools (`mempfix`) and variable heaps (`mempool`).
  - Freestanding C runtime primitives (`libstr.c`, `libaeabi.c`, `libint64.c`),
    providing NASA JPL Rule 3 zero-dynamic-allocation guarantees and avoiding any
    host C library pollution on bare-metal Silicon.


### src/cores/
Architecture-specific startup, asymmetric multiprocessing (AMP) orchestration,
and platform adaptation layers ("cores").
Each core adapts the generic B-System microkernel to a specific computing environment:
  - `core_arm64.c`: Cortex-A72 64-bit engine for Raspberry Pi 400 / Pi 4B,
    managing MMU MAIR attributes, Mailbox GPU allocations, and xHCI USB.
  - `core_yoko.c`: 32-bit ARM Yokoyama platform engine for Raspberry Pi 2/3 and
    QEMU versatilepb/raspi2.
  - `core_ps2.c`: Sony PlayStation 2 128-bit Emotion Engine (MIPS R5900) entry point,
    DMA scratchpad blitting, and GS packet dispatch.
  - `core_pc98.c`: NEC PC-9801 / PC-9821 Japanese personal computer platform core,
    managing 640x400 planar VRAM and keyboard INT 18h.
  - `core_mips.c`: SGI / MIPS Malta architecture core for MIPS32/64 R4000.
  - `core_m68k.c`: Motorola 68040 Macintosh Quadra 800 core.
  - `core_virtio.c` & `core_tkernel.c`: Generic VirtIO QEMU device driver cores.
  - `core_posix.c`: Desktop workstation simulator mapping B-System events to SDL2.
  - `core_smp.c`: Lock-free MPSC actor-isolated inter-core queue coordinator.


### src/fs/
The B-System Hierarchical File System (HFDS) and Block Layer.
Unlike flat Unix byte streams or DOS FAT tables, the TRON File System models
hypermedia networks, records, and Real-Time storage:
  - `file.c` & `vol.c`: Core file and directory operations implementing TRON HFDS.
  - `blk_mem.c`: Memory-mapped read-only root volumes (ROM disks / initrd).
  - `blk_file.c`: Host file backed virtual block devices.
  - `blk_part.c`: MBR / GPT partition table parsers.
  - `blk_qcow2.c`: Copy-on-write sparse disk image reader for virtualization.
  - `fs_stdio.c`: Freestanding stream bridges for legacy asset loaders.


### src/drivers/
Hardware device drivers categorized by hardware platform and bus architecture:
  - `broadcom/` (formerly `bcm283x/`): Broadcom BCM2711 / BCM2835 SoC silicon:
    - `gpu/`: VideoCore VI (V3D 4.2) 3D hardware pipeline, control lists (`v3d_cl`),
      QPU shader bytecode assembler (`v3d_qpu`), and mailbox interfaces.
    - `dma/`: Hardware 2D DMA blitters (Channels 0 & 7) for zero-copy scanouts.
    - `usb/`: Synopsys DWC2 and Cadence xHCI USB host controllers with 6KRO.
    - `pci/`: BCM2711 PCIe Gen 2 Root Complex and VL805 bridge initialization.
    - `cpu/`: ARMv8-A MMU page tables, cache maintenance, and armstub8 firmware.
  - `playstation2/` (formerly `ps2/`): Sony PlayStation 2 hardware silicon:
    - Direct Graphics Synthesizer (GS) rasterization, GIF packet ring buffers.
    - Vector Unit 0/1 microcode (`ps2_vu0_kernel`, `ps2_vu1_geom.vsm`).
    - SIO serial terminal, DualShock 2 gamepad pad driver, and USB keyboard.
  - `pc98/`: NEC PC-9801 GDC graphics controller, planar 16-color graphics, and
    PC-98 JIS keyboard matrix decoding.
  - `m68k/`: Apple Quadra 68040 DAFB video controllers and Mac ROM integration.
  - `mips/`: MIPS Malta 16550A UART and PCI controller glue.
  - `uefi/`: UEFI Graphics Output Protocol (GOP) linear framebuffer scanout.
  - `vesa/`: VESA BIOS Extensions (VBE 2.0/3.0) linear framebuffers for x86 PCs.
  - `virtio/`: VirtIO modern block and VirtIO-GPU para-virtualized devices.


### src/apps/
User-facing productivity, communication, and desktop applications:
  - `chat/`: B-System LAN/RTP interactive messaging and XML chat protocol client.
  - `cabinet/`: Hierarchical document cabinet, virtual object manager (`vobj_manager.c`), and databox filing manager.
  - `clarity/`: The Clarity rich document authoring and typography studio,

  - `editor/`: Canonical TRON text editor (`t_editor`) with multi-lingual TIP input.
  - `workbench/`: Classic BTRON Workbench desktop shell, task tracker, deskbar, global menus, and compositor:
    - `workbench.c`, `tracker.c`, `desktop.c`, `about.c`, `global_menu.c`, `main.c`: Desktop environment.
    - `desktop_mobile.c`, `workbench_mobile.c`, `main_mobile.c`: Mobile/FOMA phone desktop UI.
  - `volumes/`: Disk volume manager, formatter, and drive setup utility (`b_drivesetup`).
  - `clock/`: Real-time desktop analog/digital clock and calculation desk accessories.
  - `preferences/`: System configuration, display resolutions, and sound panel.
  - `terminal/`: High-performance graphical terminal emulator (`gterm`).
  - `chokanji/`: Cho-Kanji (超漢字) compatibility and interoperability engine:
    - `bpk_core.c` & `unpack.c`: BPK package installer and archive extractor.
    - `kconv.c` & `xfconv.c`: TRON Character Code (Tcode / GT code) to Unicode converters.

2. Guiding Architectural Principles
-----------------------------------

1. Zero Symbolic Links Policy (STRICT):
   No symbolic links are permitted anywhere in the repository. All files and
   directories reside at their true canonical paths. Every reference in Makefiles,
   linker scripts, volume manifests, test harnesses, and C #includes points
   directly to the physical target without filesystem indirection.

2. Zero Sub-Repositories Policy (STRICT):
   The repository is a single, self-contained monolithic tree. No git submodules,
   git subtrees, or external repository dependencies are allowed.

3. Single-Producer Invariants (ASYNC.txt):
   Every ring buffer crossing cores or hardware execution units has exactly ONE
   producer and ONE consumer. Directory structures must cleanly isolate device
   drivers from desktop compositors to prevent cross-subsystem state corruption.

4. NASA JPL Rule 3 Freestanding Compliance:
   Kernel, drivers, and desktop services must never rely on hosted C library
   dynamic memory allocations (`malloc`/`free`) during real-time rendering.
   All allocations are pre-reserved in `.nocache` or static frame pools.

5. Cleanroom Japanese Computing Heritage:
   Respects Dr. Ken Sakamura's TRON specifications while preserving compatibility
   with Cho-Kanji, BTRON3, BeOS, and modern high-resolution 60 FPS hardware pipelines.

## 1. Core Architectural Mandates

1. **Zero Symbolic Links Policy (STRICT):**
   - **No symbolic links allowed anywhere in the source tree.**
   - Every file and directory must reside at its true physical path on the filesystem.
   - All references in `Makefile`, linker scripts (`link.ld`), test scripts (`test_structure.sh`, `test_*.sh`), volume manifests (`manifest.txt`), and C source `#include` directives must point **directly** to the canonical paths without relying on `ln -s` aliases or filesystem indirection.
   - All temporary/transitional symlinks in `src/` must be completely removed upon path canonicalization.

2. **Zero Sub-Repositories Policy (STRICT):**
   - **No git submodules, git subtrees, or nested sub-repositories.**
   - The entire operating system, kernel, drivers, desktop, emulators, media, and productivity suite reside in a single, unified, self-contained monolithic git repository.

3. **Minimal, Non-Destructive Moves:**
   - Moves are performed via `git mv` at the folder level.
   - Code files are never destructively split or fragmented, maintaining git history, authorship, and NASA JPL Rule 3 zero-dynamic-allocation guarantees.

## 3. Direct Makefile & Tooling Canonicalization (Symlink Elimination)

To enforce the **Zero Symbolic Links** mandate, all paths across the build harness must be directly converted:

### 3.1 `Makefile` Source Variables
- **Broadcom Driver**:
  - `ARCH_BCM_SRCS`: Change `src/drivers/bcm283x/...` $\rightarrow$ `src/drivers/broadcom/...`
  - `PI400_CFG_DIR`: Change `src/drivers/bcm283x/pi400` $\rightarrow$ `src/drivers/broadcom/pi400`
  - `BAREMETAL_STARTUP`: `src/drivers/broadcom/cpu/startup_arm.c`
  - `BAREMETAL_LD`: `src/drivers/broadcom/cpu/link.ld`
  - Pattern rules: `src/drivers/broadcom/cpu/%.tkernel.o: src/drivers/broadcom/cpu/%.c`
- **PlayStation 2 Driver**:
  - `PS2_SRCS`: Change `src/drivers/ps2/...` $\rightarrow$ `src/drivers/playstation2/...`
  - `PS2_PW_SRCS`: `src/drivers/playstation2/ps2_paint_worker.c`
  - Include paths: `-Isrc/drivers/playstation2`
- **Quake 3D**:
  - `QUAKE_SRCS`: Change `src/quake/...` $\rightarrow$ `src/media/quake/...`
  - Include paths: `-Isrc/media/quake/include`
  - Test suites: `TEST_QUAKE*_SRCS`: update to `src/media/quake/...`

  - `CLU_APPS_SRCS`, `CLU_CORE_SRCS`, `BE_DASM_SRCS`, `SC_SRCS`: Change `src/clu/...` $\rightarrow$ `src/apps/clu/...`

  - Update `src/font/...` $\rightarrow$ `src/desktop/font/...`
